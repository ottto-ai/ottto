# Refused snapshot custody

Stale-older refusals from current servers mean the server already holds the
newer usage; earlier ones stay counted as owed. A fresh permanent
`accepted_log_stale_older_upload` follows the existing dominated, terminal
residue path. It never becomes an accepted-body ACK.

The optional `exposure` observation distinguishes fresh records written by this
collector from legacy records. Only recording a fresh permanent server refusal
writes it; loading, measuring and retaining legacy records never backfill it.
Missing or malformed observations conservatively keep stale records owed.
There is no timestamp cutoff, migration or additional persisted marker. Legacy
dispositions remain unchanged and owed debt stays in G7 counts and local logs.
Otherwise settled cycles keep successful status and the existing residue shape.

The existing refusal owner retains exact legacy body witnesses, including owed
older revisions. Identical owed bytes stay suppressed. Changed input may produce
a different body through ordinary Tail or Full acquisition, with its own offer
and exact acknowledgement. Unknown non-permanent rejection reasons, including
`accepted_log_stale_older_mixed`, use ordinary RetryPending custody for that
entity; accepted siblings settle normally. Known money-hold contracts, entity
binding and exact witness validation retain their existing checks. Unknown
permanent reasons retain their existing handling and safe classification.

A retry resends a stored body; transcripts are read again only for new bytes.
A body witness is not a stored body. Missing body custody grants no transcript
reconstruction. Legacy owed entities never ride automatic quarantine, reason
re-offer, audit or revision-triggered reconstruction paths. Their existing
cooldown view holds unchanged input independently of retry deadlines, parser
versions and upload contexts. Changed input remains discoverable.

Diagnostics extend existing refusal records, native collection page and
StageWindow with scalar owed/held counts, known requests/tokens, unknown counts
and oldest known age. Overlapping revisions contribute one observed revision
per entity. Legacy missing observations stay unknown. Only a rising owed count
triggers the existing refusal alarm; growing age alone never does. No age
buckets, additional observation window, history or retention structures are
added, and counters never grant read authority.

Claude, Codex and Pi share this custody and ACK machinery. The stale-older
reason has currently been observed in Claude only. Proofs, identity, account
attribution and server acceptance authority keep their existing contracts.
No schema or parser version changes; optional observations decode per record.

# A setting or capability flip forces no transcript read

Upload settings, the attribution key and server capabilities (cache observations, copy-unproven)
shape what is sent, never what a parser produces. No read-side identity binds them: the native
file scope, the Codex group scope and memos, the traversal, comparison skips, tier receipts and
archive contexts. The file scope also drops the replay generation (a replay clears the index
itself) and the compiled parser version (it changes only across a restart, which drops RAM
checkpoints). Delivery proofs keep the full upload context, whose formula is unchanged and pinned.

A file whose receipt proves its exact bytes and bodies at the current epoch owes delivery, not a
read, when only the context differs. The debt is paid when the file is next acquired for an
ordinary reason, and the new body is sent in the new form. The bodies stamped for every entity the
receipt covers must equal the body set it delivered, whatever context they were sent under; a
missing entity set or stamp, or an entity sent since with another body, selects. A receipt of the
active base in another copy mode is the operator's scoped copy-prefix re-read and still selects, so
a Claude file back under its own base after a partial ACK under another context reads once.

Upgrade: a traversal or carry origin saved in the earlier form is rewritten when that form,
recomputed under the active delivery context and replay generation, equals it; otherwise the walk
starts as before. Tier receipts and archive contexts still record the delivery context for older
readers but are never compared, so none is held or re-read.

Session links are always scraped; the setting and the server's 512-byte limit apply at upload, and
over-limit links are counted. Consequences: enabling a setting applies to sessions active after it
is turned on; closed sessions gain nothing unless an operator backfill is requested; a body held in
quarantine is reassessed at its deadline rather than on a context change.

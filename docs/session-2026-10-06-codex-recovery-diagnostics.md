# Local Codex census and recovery evidence

A completed transcript traversal can remain non-terminal because an existing Codex state or naming sidecar could not complete its census. Previously the terminal status journal preserved counters and the generic parse error, but omitted the loader and gate evidence needed to distinguish that condition. A superseded quarantine could also coexist with an old file association restored by partial checkpointing without recording the working-index transition that produced it.

The existing `codex-terminal-status-v1.json` journal now has an optional `local_codex_diagnostics` extension. Its receipt remains the unchanged typed status request. Only the local journal wrapper serializes the extension; neither terminal status POSTs nor snapshot upload DTOs contain it. The journal retains one latest receipt per existing destination/source, below the four-record ceiling. The extension has a 32 KiB serialization guard and a fixed, content-free schema: counts, flags, closed reason enums and domain-separated SHA-256 byte arrays. It accepts no raw paths, prompts, source ids, credentials or arbitrary error text.

The scanner observes the existing five reads: state titles, state threads, spawn edges, rollout extents and session index. Each reports completed/failed root counts, the first bounded failure class, whether other failure classes occurred, and whether that loader added identity conflicts. Missing optional sources remain complete-empty under the existing rules; a completed read alone does not assert source presence. Schema/shape failures carry a typed internal error so classification does not parse error text. Gate flags record discovery, traversal health, frozen generation, state/sidecar completion, reconciliation, parent restart, clean followup and the local scan's census result. These describe the scanner before any later terminal-policy tombstone override.

Four quarantine samples rotate by scan-index generation modulo quarantine count. Each records a hashed fingerprint, the first associated file key and total associated-file count and legacy-map flag, native parse reason and entity count, finalization completion, resulting entity count, up to four hashed successor fingerprints, available previous/final body witnesses, actual effective-body revision, current membership and actual quarantine dispositions before/after the existing supersession operation. Successor slots beyond `min(finalized_entity_count, 4)` are unused. Counts disclose truncated coverage; an unsampled quarantine has no proof. State-only or unassociated quarantines have no file lineage, and multiple-file associations disclose that only the first file was sampled. These are working-index witnesses at policy/cutoff finalization and supersession, not an assertion about the durable map after later partial checkpointing. `finalized=false` does not mean an empty successor set was proved.

No new store, scheduler, source/provider/SQL read, retry, repair, reoffer, lifecycle action or backend contract is introduced. Sampling traverses only already-owned index/progress metadata. Fixed diagnostic fields are included in the exhaustive heap inventory used by the existing source-rotation admission gate. Public #493 is already in this branch's main base.

Fault fixtures use native SQLite and JSONL loaders for row/schema failures, malformed sidecars and identity collisions; native scanning plus account cutoff distinguish successor, confirmed-empty and incomplete-file finalization. Paired controls show identical snapshot/index output with diagnostics disabled. Additional tests cover four-sample rotation, actual supersession, a historical terminal quarantine with restored current membership, bounded content-free serialization, latest-journal retention, unchanged real mock HTTP status bodies, and a real journal filesystem failure that still posts terminal status.

Installed ordinary recovery validation remains pending a containing release. Existing release 0.1.153 receipts and the original acceptance window are unchanged; source fixtures cannot certify installed census completion, recovery of any selected session, backend materialization or first visibility.

# Owned collection turns in the existing snapshot cycle

Snapshot sync now owns each source's parser, working index, committed baseline, progress ledger, policy and attribution context in one preparation frame. The existing cycle mutex and thread perform up to 64 native collection steps or 16 ms of observed work before offering another due source. A step consumes one bounded physical JSONL line, including skipped/malformed lines; it never copies raw rows into a new continuation store. File setup, metadata/parent discovery, a blocked read and finalization remain indivisible native work. This is cooperative fairness, not a wall-clock deadline guarantee.

A completed source enters the original policy finalization, effective-body preparation, exact ACK validation, progress persistence, index CAS and source-manifest path. An active partial file cannot certify source completion. The cycle pins account identity; resumed scans, fresh-token/upload boundaries and index publication check current account, device/source grant and endpoint authority. The existing fresh destination check remains required. Discarded working state recovers through the canonical durable index and exact ACK ledger.

Parked preparation graphs share an 8 MiB requested-layout admission ceiling, including spare queue capacity. This reserves 24 MiB of the same 32 MiB overlap budget for any separately admitted optional complete-body send; it is not a second budget or a universal transport bound. An exhaustive field walker charges capacities, supported container nodes and full nested owned context. It conservatively counts an empty allocated BTree root, bounds traversal work and checks arithmetic. Its fixed container assumptions are admitted only for Rust 1.88.0 on 64-bit macOS. Unsupported layouts, opaque cache JSON, retained native raw bootstrap rows, excessive traversal or insufficient budget continue the same frame serially without reopening the file.

The new offline integration uses the actual rotation driver, native owned scanners, full preparation frames and the real sync mutex on one thread. A generated 120-line Pi file models six seconds per line, while native Codex/Claude siblings model five seconds of completed-source work each. Both siblings are offered before the second Pi line. Whole native scan results and indexes match uninterrupted scans. Account/destination/stop injections discard the incomplete frame and ordinary recovery reproduces the full result. Opaque-state and zero-budget controls complete serially. Existing canonical complete-body send adapters exercise fresh fake tokens, native request/gzip/ACK/report and checkpoint behavior alongside these owned turns.

The allocator probe reports Rust requested layouts separately from allocator usable bytes and incidental process RSS. Generated 1/50/1,000-hour shapes are evidence for those inputs, not a physical-memory or fleet guarantee. Transport, credentials and clock are deterministic adapters; no live provider call or installed-daemon change is part of the proof. The runtime change adds ordinary source rotation inside the existing cycle. Optional retry scheduling, a new scheduler and cadence changes are outside this change.

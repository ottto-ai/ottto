# Required copy-index decoder: inactive mechanical checkpoint

The incomplete copied-request containment prototype needs memory permission
before copying or decoding its independent held-revision ledger. Ordinary
serial index storage is baseline; new decoder/copy owners compete with the
existing process cache inside its existing 31 MiB remainder. This is requested
allocation accounting, not daemon RSS or a whole-index size limit.

This checkpoint adds an **unwired decoder and copy helpers**, not production
loading, save/CAS or settlement integration. Production remains disabled, with
no CLI/environment switch. It does not fix installed rereads or establish
containment, healthy-progress, unique-owner, ACK or performance acceptance.

The root adapter delegates the actual serde field/key decisions. Only the
existing held subdocument is captured through guarded reads. One non-retaining
costing visitor over the captured value counts entries, strings and maximum
token scratch; the original typed serde seed makes every validity decision.
No new JSON parser, persisted field, native request-ID graph, dependency or
serde feature is introduced. The actual derived root-field signature must
match before required decoding; escaped keys and sequence order retain the
original semantics.

Raw input growth, parser scratch, error formatting and typed tree allocation
are prepaid. Credit transfers to a serde-skipped runtime field after parsing.
Independent clone/selection owners need independent credit; infallible Clone
marks a required copy unpaid. Optional cache clearing cannot refund live
credit. The private Arc wrapper exposes no Weak handles and retires its Arc
allocation before returning its reservation, using the pinned standard-library
Arc::into_inner behavior.

The new profile is macOS/aarch64, Rust 1.95.0, serde_json 1.0.149,
serde/core/derive 1.0.228, zmij 1.0.21 and the existing default/std/json feature
closure. Unknown profile/layout or unavailable credit refuses before capture;
the general existing layout gate is not broadened. Current CI and packaging
commands pass no extra JSON feature flags. Passing negative controls on an
unsupported compiler is **not positive execution** of the admitted branch.

Selection preflight uses borrowed cardinalities and affected keys, without an
allocated fingerprint set or per-held whole-index walk. It conservatively pays
the full affected temporary collector, including Vec/sort/tree overlap, when
held selection can increase its size. Actual incremental allocations must be
reported separately. Existing restore calls and checkpoint/debt semantics stay
unchanged. The helpers are not a qualification of later manifest/status
consumers, ordinary producer growth or native completion.

Six tests are authored for actual derived fields; canonical escaped/map/sequence
and invalid shapes; reservation lifetime, independent clones, clear and refusal;
prepaid capture refusal; four pure live carriers and large old-payload refusal;
and collector capacity boundaries. Compilation and execution are pending hosted
CI. No local Cargo build/test or reviewer was run. On an unsupported layout,
positive allocation/decode branches explicitly report UNEXECUTED.

Remaining before runtime attachment: audit every load/save/selection/restore
consumer and error lifetime, wire the four actual carriers with fallible failure
propagation, pay existing new-debt producer growth, complete native cache and
wake custody, exact durable drain and status, execute supported positive paths,
validate normal/partial/shed/CAS and identity parity, review, and measure the
installed application. This draft has no merge or release readiness.


## Private status and consumer ownership checkpoint

The draft now includes a private, move-only, single typed observation slot.
Its fixed timestamp/counts/basis are prepaid before one Box allocation;
replacement reuses the box, equal payloads keep their id/time/sequence, and
clearing keeps the private sequence high-water mark. No generic event history
is retained by this new owner. The ordinary scan producer is not switched to
it yet. A private initial status projection prepays materialized event copies
and full vector growth overlap; a lexical guard in the control Status arm
covers its second canonical projection and owned JSON conversion. Status
reads do not advance the observation sequence; canonical upload exclusion
remains exact. Optional observation failure does not clear required scan debt
or establish that there are no holds. Other control consumers remain unqualified.

Copies retained by API callers after ownership transfer are outside the scan
cache's shared 31 MiB allowance. No public Clone/schema or transport concurrency
change is proposed. Socket response/value buffers remain live through the
existing write timeout. XPC retains its String/CString/duplicated C buffer
through the existing shim's copy/send/free sequence. Those are fixed per-output
representations, not a shared aggregate claim over arbitrary response lifetimes.
For complete serialized output size B, the reporting-only conservative Rust
buffer-growth representation is 4 * max(B, 128); String/CString/duplicate overlap
is 6 * max(B + 1, 128). These include unchanged baseline bytes, are not allocation
admission gates, and do not measure opaque XPC-framework memory or daemon RSS.
No reservation crosses the C ABI; transport free/timeout behavior is unchanged.

A borrowed scalar preflight also accounts for legacy last-fingerprint strings,
owned entity collectors and the manifest's fat-reference collector, without an
allocated affected-fingerprint set or per-held whole-index walk. Actual scan
consumer reservation/lifetime hooks are still unwired. New-debt/native cache
owners, the other internal consumers and full normal/partial/shed/CAS execution
remain required before activation.

Ten further tests are authored for actual CAS/manifest lifetime, consumer and
Vec growth boundaries, API ownership transfer, fixed stack representation,
prepayment/reuse/drop/refusal with required debt intact, actual daemon repeated
reads/interleaved sequences, structural drift, and the actual control Status
arm. These tests have no execution acceptance yet. Positive supported-layout
branches explicitly report UNEXECUTED when the pinned profile refuses; ordinary
allocation characterizations do not authorize required-path admission. The
previous 55-test CI head does not validate this new checkpoint. No local Cargo
or model review ran. This draft still has no merge or release readiness.

## Pre-offer producer and escaped-set custody slice

The opened-file handoff is now a borrowed view of the same current page's
pending finalization inputs, avoiding its former pre-fold Vec allocation.
The required producer first makes a nonallocating borrowed cost plan, then
reserves temporary revision-map/peer collectors, affected ledger growth and
returned withholding storage before running the existing overlap decision.
The exclusion rule, record/peer limits, held revision semantics and single
native fold are unchanged. Stack hex encoding retains the exact request and
source-owner hash domains; the exclusion callback borrows its family root.
Repeated peer observations deliberately overcharge the plan and can refuse
one preparation; no new cap or eligibility is inferred from that refusal.

Returned withheld IDs have their own immutable private owner and reservation.
Required disposition clones share that physical storage instead of silently
copying unreserved IDs. Credit remains live after the scan index is dropped,
after optional cache clearing and until the last returned clone retires.
The private Arc wrapper exposes no Weak handle and releases its allocation
before its reservation. Ordinary inactive callers retain their prior behavior.
No public Clone signature, persisted field or protocol changes.

A funding failure is an explicit resource refusal, never an empty withheld
set or successful filter. Filtering returns an error without removing candidate
bodies; the local evidence path exits before C5 tagging, and the actual source
finish propagates refusal before binding, offer or save, preserving last durable
state. This slice cannot truthfully retain an exclusion without its storage,
so that preparation aborts rather than claiming healthy progress or installing
a permanent whole-source hold. Native capture/wake/admission remains separate
and inactive.

Three further regression tests are authored: borrowed-plan zero allocation and

clone/credit lifetime. The last positive branch remains UNEXECUTED if the real
profile refuses. Source and tests await their own hosted CI; no local Cargo or
model review ran. Installed CPU, RSS and rereads remain unproved.


## Actual required preparation and terminal carrier wiring

The inactive test-opt-in required path now loads with the real shared owner,
uses the fallible committed-index clone, and reserves context inputs before
constructing the registry path, scope, registered-slot digest or attempt string.
It uses the already-borrowed source support root and existing settings filename;
ordinary callers retain their prior default-path and decoder behavior. Scope
and attempt hashes retain their exact byte domains. Missing or changed settings
remain unknown; funding refusal explicitly aborts required preparation.

An additive prepaid registry getter reuses the existing strict regular-file,
no-follow, 1 MiB read, typed serde decoder and validator. It asks for credit
before input allocation using the opened length plus sentinel. That length is
only a size preflight. The new entry rejects growth, truncation or observed
path replacement, never treating metadata as identity or revision permission.
A second preflight covers validation/NFC and the retained decoded graph before
validation allocates. Existing callers do not use these new hooks.

The closed serde bound charges vector doubling/old-new overlap using actual
slot/operation layouts and an input-byte element upper bound; it also charges
raw/owned strings, parser scratch and escaped errors. The validation bound
uses nonallocating canonical decomposition counts for NFC buffers and output,
and existing9/18 limits for validation trees, service strings and reference
sorting. Decode data stays funded through validation and digest transfer.
The bound is deliberately conservative: large valid registries can refuse
required preparation before allocation. This is not a new data-policy cap,
a measured peak, or activation/performance acceptance.

Terminal/deferred selection and final held restoration now propagate their
existing fallible API errors. All restore operations remain. Final restoration
also pays its existing induced current-entity/manifest collectors. Ordinary
source operations, ACK/body rules and correction decisions stay unchanged;
there is no ordinary/unpaid fallback for a required owner. Failures preserve
the last durable index/debt and do not synthesize an eligible empty state.

Three additional tests are authored for registry refusal-before-input and

terminal/deferred/CAS cases, and actual owner pressure/clone/selection/restore

## Required parser-to-completion provenance

The inactive required context now owns one private generation-scoped provenance
sidecar, funded by the existing reservation before its Arc or vector backing is
allocated. Complete native parser finalization records only fixed full digests
of the actual candidate root/path, opened revision and parsed session. Aliases,
incomplete parses and missing/unsupported/unfunded state supply no completion
witness. No raw paths or native request IDs are retained by this carrier.
PendingIndexFinalization remains unchanged; ordinary scans allocate no sidecar.

SourceScanResult carries one inline process token. Its Clone drops the token;
index/context clones share immutable paid metadata but cannot write, seal or
claim source completion. Growth reserves before vector reallocation; a shared
old version retains independent credit while a real fixed-digest copy is paid.
All private Arc retirement frees its allocation header before returning credit.
The original source seals once at completion. At F1, after the authoritative

path/revision/session and ambiguity checks consume that same carrier. Borrowed
reference collectors are prepaid before allocation and sorted for bounded
lookup work; no native-ID graph is cloned or walked. Metadata remains lexical
through C5, then retires. Selected, cloned, reset and reloaded contexts cannot
turn it into a different source completion. Optional failure changes no body,
ACK, held debt, identity or read decision.

Three new actual-path regressions cover ordinary no-carrier/no-allocation;

## Native input escrow through the actual return

The inactive source now consumes the same parser provenance and exact matching
implementation to extend held native ID storage across F1, qualification and
the actual F3 return. Existing scope/generation/root/path/revision/session
checks remain. Matching preserves original input ordinals in prepaid borrowed
reference collectors. Before output backing or any ID move, the existing owner
reserves the descriptor vector and the full requested-layout bound of each
native set whose lifetime will extend. Only copied-withheld complete inputs
move, using their actual BTreeSet nodes and String allocations. Healthy inputs
stay in place through qualification. Missing, refused, ambiguous or unfunded
input produces no escrow and does not alter body, debt or read eligibility.
The optional producer-refusal predicate allocates no extra error.

The returned owner is move-only. Its vector and ID graphs retire before source
provenance and input reservations return. It survives the actual function
return; the real source caller then drops it before later required upload or
selection allocations. Standalone callers use the same implementation and
retire at that boundary too. No cache insertion, lookup, callback or W4 wake is
enabled, and no additional native read or settlement result consumes this
escrow. It is not a memory/RSS or installed reread improvement claim.

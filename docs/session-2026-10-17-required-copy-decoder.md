# Required copy-index decoder: inactive mechanical checkpoint

The incomplete copied-request containment prototype needs memory permission
before copying or decoding its independent held-revision ledger. Ordinary
serial index storage is baseline; new decoder/copy owners compete with the
existing process cache inside its existing 31 MiB remainder. This is requested
allocation accounting, not daemon RSS or a whole-index size limit.

This checkpoint adds an **unwired decoder and copy helpers**, not production
loading, save/CAS or settlement integration. Production remains disabled, with
no CLI/environment switch. It does not fix installed rereads or establish
containment, healthy-progress, unique-owner, ACK or performance acceptance.

The root adapter delegates the actual serde field/key decisions. Only the
existing held subdocument is captured through guarded reads. One non-retaining
costing visitor over the captured value counts entries, strings and maximum
token scratch; the original typed serde seed makes every validity decision.
No new JSON parser, persisted field, native request-ID graph, dependency or
serde feature is introduced. The actual derived root-field signature must
match before required decoding; escaped keys and sequence order retain the
original semantics.

Raw input growth, parser scratch, error formatting and typed tree allocation
are prepaid. Credit transfers to a serde-skipped runtime field after parsing.
Independent clone/selection owners need independent credit; infallible Clone
marks a required copy unpaid. Optional cache clearing cannot refund live
credit. The private Arc wrapper exposes no Weak handles and retires its Arc
allocation before returning its reservation, using the pinned standard-library
Arc::into_inner behavior.

The new profile is macOS/aarch64, Rust 1.95.0, serde_json 1.0.149,
serde/core/derive 1.0.228, zmij 1.0.21 and the existing default/std/json feature
closure. Unknown profile/layout or unavailable credit refuses before capture;
the general existing layout gate is not broadened. Current CI and packaging
commands pass no extra JSON feature flags. Passing negative controls on an
unsupported compiler is **not positive execution** of the admitted branch.

Selection preflight uses borrowed cardinalities and affected keys, without an
allocated fingerprint set or per-held whole-index walk. It conservatively pays
the full affected temporary collector, including Vec/sort/tree overlap, when
held selection can increase its size. Actual incremental allocations must be
reported separately. Existing restore calls and checkpoint/debt semantics stay
unchanged. The helpers are not a qualification of later manifest/status
consumers, ordinary producer growth or native completion.

Six tests are authored for actual derived fields; canonical escaped/map/sequence
and invalid shapes; reservation lifetime, independent clones, clear and refusal;
prepaid capture refusal; four pure live carriers and large old-payload refusal;
and collector capacity boundaries. Compilation and execution are pending hosted
CI. No local Cargo build/test or reviewer was run. On an unsupported layout,
positive allocation/decode branches explicitly report UNEXECUTED.

Remaining before runtime attachment: audit every load/save/selection/restore
consumer and error lifetime, wire the four actual carriers with fallible failure
propagation, pay existing new-debt producer growth, complete native cache and
wake custody, exact durable drain and status, execute supported positive paths,
validate normal/partial/shed/CAS and identity parity, review, and measure the
installed application. This draft has no merge or release readiness.


## Private status and consumer ownership checkpoint

The draft now includes a private, move-only, single typed observation slot.
Its fixed timestamp/counts/basis are prepaid before one Box allocation;
replacement reuses the box, equal payloads keep their id/time/sequence, and
clearing keeps the private sequence high-water mark. No generic event history
is retained by this new owner. The ordinary scan producer is not switched to
it yet. A private initial status projection prepays materialized event copies
and full vector growth overlap; a lexical guard in the control Status arm
covers its second canonical projection and owned JSON conversion. Status
reads do not advance the observation sequence; canonical upload exclusion
remains exact. Optional observation failure does not clear required scan debt
or establish that there are no holds. Other control consumers remain unqualified.

Copies retained by API callers after ownership transfer are outside the scan
cache's shared 31 MiB allowance. No public Clone/schema or transport concurrency
change is proposed. Socket response/value buffers remain live through the
existing write timeout. XPC retains its String/CString/duplicated C buffer
through the existing shim's copy/send/free sequence. Those are fixed per-output
representations, not a shared aggregate claim over arbitrary response lifetimes.
For complete serialized output size B, the reporting-only conservative Rust
buffer-growth representation is 4 * max(B, 128); String/CString/duplicate overlap
is 6 * max(B + 1, 128). These include unchanged baseline bytes, are not allocation
admission gates, and do not measure opaque XPC-framework memory or daemon RSS.
No reservation crosses the C ABI; transport free/timeout behavior is unchanged.

A borrowed scalar preflight also accounts for legacy last-fingerprint strings,
owned entity collectors and the manifest's fat-reference collector, without an
allocated affected-fingerprint set or per-held whole-index walk. Actual scan
consumer reservation/lifetime hooks are still unwired. New-debt/native cache
owners, the other internal consumers and full normal/partial/shed/CAS execution
remain required before activation.

Ten further tests are authored for actual CAS/manifest lifetime, consumer and
Vec growth boundaries, API ownership transfer, fixed stack representation,
prepayment/reuse/drop/refusal with required debt intact, actual daemon repeated
reads/interleaved sequences, structural drift, and the actual control Status
arm. These tests have no execution acceptance yet. Positive supported-layout
branches explicitly report UNEXECUTED when the pinned profile refuses; ordinary
allocation characterizations do not authorize required-path admission. The
previous 55-test CI head does not validate this new checkpoint. No local Cargo
or model review ran. This draft still has no merge or release readiness.


## Required file and partial-checkpoint integration slice

An explicit paid file-load entry now uses the guarded decoder and the same
strict validity/canonicalization checks. Unknown profile refuses before file
IO; missing-file defaults also acquire real required credit. The ordinary
native producer is not attached to this entry. Required saves derive the same
shared owner from their index credit and use it for the competing CAS decode
under the existing lock, without recursively calling a locking load. Unpaid
required clones refuse before IO. The existing bounded input/shape checks and
ordinary save behavior remain.

The actual partial-checkpoint function now uses fallible selected-index and
held-restore operations. Selection and induced consumers reuse one frozen
borrowed fingerprint cardinality and prepay their collectors. Both existing
restore operations remain. A failed shed checkpoint borrows the unchanged
committed index for status instead of deep-cloning its ledger.

Two additional tests are authored for strict invalid/missing paid loads and
actual progress-lock/partial-selection/save/CAS success and failure, retaining
exact held debt and old accepted file state. They include healthy synthetic
no-body progress, refused unpaid clones and preserved bounded-read limits.
They are not native-parse, ACK, money/identity or installed acceptance. The
supported carrier path explicitly reports UNEXECUTED when the real profile
refuses; there is no layout bypass. This source slice has no compile/test
acceptance until its own automatic CI completes.

The existing record_known_copy_holds producer's opened-file/revision map,
peer/root/hash temporaries, new/revised hold allocation and returned withheld
set still require prepayment and custody through their actual lifetimes.
Native capture/event/context gaps are separate. These remaining owners prevent
native attachment, activation, intake, merge and release. Optional status scope
is frozen; no transport or broader control change belongs to this slice.

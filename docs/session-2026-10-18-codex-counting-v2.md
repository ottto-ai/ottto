# Codex usage counting V2 (inactive until a reviewed cutover)

Codex writes two usage streams: UI `token_count` events and, in newer CLIs, native `token_usage_record`s with a per-response `usage` and the thread counter after it. Today the parser counts only the UI stream. That double-counts equal-total re-emissions and misses work the UI never reports, such as compaction responses.

New sessions can now use an occurrence reducer (`snapshots/codex_usage_occurrence.rs`):

- Natives are counted by their coverage of the thread counter, one dimension at a time. A native that starts at the previous high-water mark counts its `usage`. A restatement of covered counters counts 0. On overlap only the part not yet covered counts: `max(0, after - max(before, hwm))`. A gap counts its `usage`. A conflicting restatement under the same response id is reported.
- Turn UI is held as pending rows until its turn closes. A turn with a native drops its UI; a UI-only turn publishes it at closure. A native that arrives after closure counts 0. Pending is capped at 64 rows, each with at most 4096 bytes of content. The first overflow publishes the turn's UI, and natives for that turn then count 0. UI outside any bound turn keeps today's rule.
- Closure is final. The last 64 closed turn ids are kept exactly. Every closed id also goes into a fixed 8 KiB filter (four bit positions from SHA-256, with no per-process seed), which is never cleared within the session. A `task_started` or a native whose id hits either one opens only an unbound span, where natives count 0. A filter hit outside the exact ring is reported as unconfirmed, since it may be an older closure or a false positive. A false positive can only undercount natives; it never counts UI twice.
- Inside a bound turn, an equal `last`/total re-emission with no native in between is dropped. A last-less first or reset cumulative base is not counted.

The counting version (`snapshots/codex_counting_version.rs`) is decided once per session from the root `session_meta` creation timestamp, a compiled cutover, and this destination index's existing acknowledgement evidence. A session already acknowledged by a writer that did not mark V2 stays Legacy. In a session view (twin, alias or joined members), any Legacy-acknowledged entry forces Legacy, and entries without acknowledgement are neutral. A joined group configures its counting state once, on its replay parser, and carries it across members. A V2 group marks every member; a Legacy group clears any stale mark along with the acknowledgement it rewrites. The local index bool `codex_counting_v2` moves atomically with its entry's acknowledgement fields. The compiled cutover is `None`, so every session stays on Legacy counting, byte for byte. Turning V2 on is a separate reviewed change. It must freeze one instant after the grouped-parser path is configured. A retained reduction is reused only when the fresh parse's evidence would select the same counting rule.

Each finished V2 parse adds its receipts to a fixed-size `codex_counting_v2` block of the local-only Codex scan diagnostics: late, flushed and restated natives, dropped UI repeats, uncounted bases, closure mismatches, reopened turns and unconfirmed filter hits. A singleton and a joined group each fold once. The block also carries the parse's still-open UI-only turn debt: `open_turn_ui_pending_*_this_scan` sessions, events and usage. That debt is visible only in the scan that parsed it. The block is written to the terminal journal and is never sent.

Pending-state heap is charged through the existing requested-layout accounting. Byte pressure never changes what is counted: the row and content caps depend only on content. The worst-case staged content is 64 × 4096 B = 256 KiB per session. On top of that come the row and selector map structure and string overhead, the fixed reducer, the 64-id ring and the 8 KiB filter. The requested-layout charge of a full staged turn is therefore well above 256 KiB. It is a conservative accounting bound, not RSS. Disclosed residuals: if the destination index is lost, a post-cutover session acknowledged by an old binary re-derives V2. A binary downgrade after V2 publication is not fenced. R-sticky: inactive cutover-None parses can clear V2 marks, making those sessions permanently Legacy after reactivation; activation must explicitly choose carry vs clear. The mark becomes durable only with the saved selected local ACK facts, not with server acceptance.

Unchanged: wire contract, cadence, Claude parsing, Legacy output. Tests run in Public CI only: eight counting regressions, version and acknowledgement controls, a reopen far beyond the ring, one group fold, and one held-versus-saved selected index boundary for a member mark.

# Codex prelude footprint

New module `codex_prelude_footprint.rs`. It answers what every new Codex session loads before its first request: the AGENTS.md chain and the skills listing. Before this, Codex instruction-file sizes were collected nowhere, and composition dropped the AGENTS.md text entirely (fixed separately in #598).

One parser: `CodexPreludeParser` takes rollout rows already decoded (`observe(&Value) -> More | Done`, then `finish()`), so the session sink can share it instead of parsing the prelude a second time. `parse_prelude` is the same parser over a bounded reader. It needs `world_state` (cli >= 0.159); older rollouts are not supported, and only `content_item_kinds`-labeled message blocks count toward hook and other harness text.

How it runs: inside the existing Claude Code footprint thread, right after each footprint cycle (every 6 h; no thread or schedule of its own). It reads only the prelude of each NEW rollout under every registered Codex root (`snapshot_roots::registered_scan_roots`: `~/.codex` and accepted Ottto slot homes, `sessions` and `archived_sessions`), against the home that wrote it (its user `AGENTS.md`, skills and `config.toml`). Bounds: 200 lines and 2 MiB per prelude, plus up to 8 rows after the first request when the context window is still unknown (locally p50 15 lines / 164 KB, p99 334 KB). A local index (`<support>/codex_session_start/index.json`) remembers each final prelude; at most 400 new preludes per cycle. Forks and copied parents are skipped (same rule as the session sink).

What it uploads: per repository scope, the newest owned fresh start, through the existing `POST /api/v1/context-footprint/snapshot` (`agent_source = "codex"`, `counter_source = "codex_rollout_prelude_chars_v1"`). `captured_at` is the session start, not the upload time: one rollout is one observation and is never sent again. A newer start with the same sizes is sent at most weekly. A scope whose newest start was already sent does not take one of the 12 per-cycle slots.

- Units: item and category `tokens` are UTF-16 **character** counts and category `pct` is 0. The backend owns the character-to-token ratio and converts on admission. `used_tokens` is the exact first-request input.
- `memory_files`: user-level AGENTS.md (`source = "User"`) and each project chain file (`source = "Project"`, repo-relative path), with `truncated_by_limit`. A file loaded whole gets `file_bytes`, `file_lines`, `file_chars` and the device-salted `content_hash` from the shared `context_file_counts::measure_bytes` (same function and recipe as the Claude file counts, #600). A trimmed or cut file sends only its `stat` `file_bytes`, omitted above the 1 MiB admission bound. No `loaded_lines` (Claude's line limit).
- The chain split mirrors Codex's loader (override name first, blank-line joins, total capped at `project_doc_max_bytes`, default 32 KiB, read from the home's top-level `config.toml` via the secure Codex config reader and `toml_edit`). `agents_md_cut(text, limit)` is the shared truncation rule, also for the per-session `instruction_load_cut` flag.
- `skills`: one item per listing line with its root kind (Project, User, System, Plugin, Other). Categories: `System prompt`, `Memory files`, `Skills`, `Hook context`.
- Not included: `additional_tools` / Codex Desktop `codex_app` tool-schema size (D7 belongs to session_start, CROSS-LANE S12).

Order: the backend converts `codex_rollout_prelude_chars_v1` characters to tokens with its `start_parts` ratio table (`start_parts_ratios_v1`), recomputes category `pct`, admits `Hook context` as part `hooks_env` (owner "yours"), and rejects any category without a Codex ratio (coding-agents-observability #11287). That backend must be live before this ships. No release is part of this change.

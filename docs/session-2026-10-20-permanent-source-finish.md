# Permanent-refusal source finish

A completed Claude source cycle can settle transport while retaining exact
permanent refusals as visible error debt. Its permanent-success return used to
bypass the common native-comparison lease finalizer, even when the cycle had
independently earned a complete native conjunction and durable selected save.
A carried refusal reproduced the same exit without another upload.

The permanent-success branch now reaches the existing finalizer only after a
successful terminal status call, fully settled upload, a clean selected page,
and either the actual complete native conjunction or a currently allowed lease.
Otherwise it keeps the previous successful transport return and conservative
lease drop. Retryable outcomes keep their error return. Normal success keeps
its existing finalizer and status behavior.

No refused body becomes accepted. Exact refusal records, quarantine, status
error disclosure, ACK validation, selected saves, retry/cadence, scope, caps and
persisted/wire formats retain their existing rules. No lifecycle implementation
or acquisition/cache policy changes are included.

The regression runs real preparation, owned native collection, evidence fold,
uploader and source finish against synthetic local transcripts, paired evidence
and HTTP responses. It establishes a refusal, appends only whitespace to change
the physical source revision while preserving the body, then checks the carried
refusal finish and actual next same-context preparation. Retryable conflicts,
failed terminal status and a genuinely unclean native census are negative
controls. A separate positive preserves native census admission without optional
paired sidecars. Existing
normal-success, exact-ACK, partial/shed, restart, context and failed-CAS controls
remain unchanged.

Automatic CI at baseline 82095f38 reached the carried-refusal cycle's real
complete conjunction and selected save, then observed an abandoned lease where
a valid lease was expected. It also exposed a separate test-fixture error: a
retryable response incorrectly used a non-permanent rejection. The fixture now
uses the existing conflict response; the production validator is unchanged.
Candidate 77feae8d passed carried-refusal and actual next-cycle admission, plus
retryable/status controls. Its remaining fixture failure incorrectly assumed
absent optional paired sidecars invalidate a complete native request census.
That assumption is superseded, not a production defect: the explicit no-sidecar
control expects native admission, while a malformed physical transcript line
supplies the actual unclean-census negative. Production gates are unchanged.
Corrected candidate CI and independent review must pass before intake.

This repairs a demonstrated source exit discrepancy. It does not establish the
cause of installed scan bursts, healthy request coverage, a memory leak, or
installed CPU/RSS savings. No release or installed runtime action is included.

# Request money integration with current main

This integration retains the inert Codex continuation hooks and Claude frozen
extent behavior from main. Ordinary preparation and continuation preparation use
the same upload-context helper. Codex continuation carries no Claude money policy;
Claude custody remains behind its existing activation gate. Both money activation
constants remain false and the maximum gated Claude revision remains 2.

Every family deadline advances over the same asynchronous custody wait; a
writer receipt after family zero cannot exhaust later families' money-only
window. The OFF shadow skips live release-custody lookups and uses the existing main
newborn-only would-hold accounting. Full entity bodies still use the one shared
builder. Canonical query spelling reuses the existing hexadecimal encoder.

Writer tickets now request bounded dirty data, between 64 KiB and the existing
8 MiB page ceiling, instead of discarding 8 MiB on each small-update restart.
The same writer persists the ticket before granting it and separately charges
physical attempts. Both 64 MiB daily caps, rollback handling, damaged-counter
refusal and checkpoint ordering remain unchanged. The existing forty-context
restart regression covers this admission behavior.

Tests retain their assertions. Large-selector fixtures use one long selector
and ordinary selectors on the remaining responses so capture fits main's work
cap while full-body admission remains discriminating. Async transport fixtures
distinguish catalog maintenance from completed retained finishes and inject
changes after an actual custody checkpoint. Unsupported ACK witness versions
still fail closed before intent or POST. Validation runs in CI; this change does
not activate collection or authorize a release.

The lost-member regression also observes the actual scope-walk key visits.
Indexed and retained census file keys are visited once; telemetry/message ledger
keys are excluded. Visits stay within the key count funded by scope admission.
A caller-thread I/O receipt asserts zero filesystem operations, independently
of the asynchronous writer, so the walk spends none of the page read budget.
The original lost-debt and undecided verdict assertions remain.

# Large-record restore Linux follow-up and main integration

A direct cold restore must classify a verified same-context audit carrier before
asking for an entry-derived expected binding. An absent index entry is precisely
one missing-custody case. Returning NoEntry first hid that evidence and skipped
the audit-carrier diagnostic. For an absent entry, carrier validation now precedes expected binding
construction, matching the existing predecessor branch and main ordering.
Indexed entries keep real-edit and accepted-floor checks ahead of carrier rearm;
a combined clean-index/debt-bearing-record/shrink control pins that precedence. It
imports no membership, checkpoint debt, mutation proof or ACK. Regression arms
use a write-only transcript descriptor: the matching context must return exactly
AuditCarrier and count it once; a foreign context must return exactly NoEntry
and count none. Both retain the exact record bytes and zero restores/held keys.
Existing deadline, clean-byte, reset/rearm and verified replacement checks remain.
The earlier writer-fixture repair alone did not close this production defect.

The common-hold fixture previously expected a cold Claude owner to delete an
absent known record without original-binding proof. Strict mutation custody
requires that survivor to remain. The fixture now asserts its preservation,
exact mutation-unproved accounting and zero GC deletions. Codex retains its
positive deletion control. Every held/no-body, counted corrupt rebuild and gate
precedence assertion remains. This changes the stale cleanup expectation, not
the mutation gate.

The near-cap threshold remains at least 90 percent of each existing source cap.
The fixture and diagnostic prose now pin the actual caps: Claude 512 MiB,
Pi 256 MiB, Codex 2 GiB. Threshold-minus-one must refuse near-cap permission;
the exact threshold must admit it. No production cap or pace was changed.

Main was merged rather than rebased. Its account-window retention, continuation
and diagnostic changes remain, while the restore integration keeps funded input
before classifier work, all-member refusals, pre-fence settlement probes, strict
mutation/receipt custody, seven refusal slots and cheap edit checks before
repeatable resource refusals. Main's capture-mode fixture alignment is retained.
The five pacing dispositions, immutable spend ledger and single shared paced
map remain. Growth discovery and audit/clock policy remain separate owner
integration dependencies. No local Cargo tests or CI dispatch were run; package
Clippy compiles all test targets without executing them. Runtime verification
belongs to the next Linux run on the published head.

The cumulative component exceeds the approximate 1,000-line guideline because
one logical restore change includes its non-optional funding, persistence,
ownership, recovery and cross-source regression fixtures. It remains one branch;
no stacked PR or independent dependency rollout is introduced.

# Large-record restore Linux failure repairs

The accepted-body floor must not suppress an independently proved native edit.
A source-verified Claude census can prove truncation only when it binds the exact
committed fingerprint and modification time to the currently opened device/inode.
That proof runs before optional restore or retail admission. A proved edit drops
an obsolete optional graph before releasing transfer credit and takes the native
Full path. Missing, stale or unknown identity evidence retains the floor; a future
accepted revision still holds. An unverified lossy read's raw byte extent is not
a verified accepted-body prefix, so its owed native audit can repair a truncated
terminal row. These changes preserve the existing real-edit precedence and do
not authorize mutation, ACK, census settlement or a new replay.

Regression fixtures retain exact native acquisition and body equality for truncate,
empty comparison parse and recovered terminal loss. The warm truncate control
now requires one native read of the changed body, cold-body equality, unchanged
ACK witness and zero subsequent body reads. Negative census controls require the
exact committed fingerprint, stamp and physical object. Unknown-original and
future-revision floor controls remain intact.

Other failures were fixture-contract mismatches. Writer-gated permission repair
and pre-injection startup sync use the real daemon lock registry. Inventory and
compatibility-debt writer fixtures establish exact Claude predecessor proof on
the same store. Unchanged content is counted clean and preserves its stored
generation; the original debt bytes still match the pinned old-reader encoding.
Attribution toggle directions use independent stores rather than silently
replacing a differently bound survivor. Capture-only preparation reuses under
the source-derived capture rule; all genuine incompatibility and unique-custody
rejection assertions remain. The store reserve assertion includes both approved
RAM maps carved out of the existing cache cap. Diagnostic fixtures distinguish
raw store snapshots and active-credit telemetry from the single state-change
alarm instead of treating every record on the carrier as a new disable.

Package Clippy compiles test sources but does not execute them. Linux runtime
validation belongs to the integration owner on the final frozen head. No local
Cargo test or CI dispatch is part of this repair. Source caps, format, allowlists,
resource budgets, shared pacing and the five prior pacing dispositions remain.

# Owned acquisition preparation

The sampled scanner keeps the original Taken until preparation succeeds. The
owned prepare API checks source, capture, counting/priority compatibility and
the physical ReadPlan before moving native state. Rejection returns the same
boxed Taken, including admission rank, finalization charge, held-new flag and
unique custody. Known-custody holds preserve accepted census only under the
existing physical-object and committed-entry rules and do not mark unreadable.
Fresh preparation and ordinary independently detected edits retain native Full
behavior; custody-bearing incompatibility is not a read grant.

Custody moves through the cache entry, Taken and completed acquisition. During
native reads the existing Plain input's NativeFile remains the sole owner.
There is no second parser owner or retail allowance map. Successful completion
ends its retail read guard without clearing the spent process allowance. Cache
return preserves fixed metadata under one retained lock, within existing entry,
state, cursor and side reservations; failed ordinary admission keeps no graph.
Dynamic owed admission and receipt logic are separate later work.

Cold restore still passes through cache admission. Active-only restore, decoder
funding, live preparation/commit and source-table changes are not enabled here.
The static branch has formatting/diff validation only; its synthetic native and
rejection fixtures require authorized CI and native/money qualification.

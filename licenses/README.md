# Third-party license notices

The macOS release ships these license files:

| File | Where it ships |
| --- | --- |
| `LICENSE`, `NOTICE` (repository root) | Ottto's own code. |
| `LICENSE-THIRD-PARTY.html` (repository root) | Generated notices for every third-party Rust crate in the `ottto` CLI and `ottto-service` daemon. |
| `licenses/Sparkle-2.9.2-LICENSE` | Sparkle, the macOS app's updater framework. Ships as `LICENSE-Sparkle.txt`. |

`scripts/macos_package.sh` puts all four into `Ottto.app/Contents/Resources`
before the app is signed (the exact names come from
`ottto_app_license_resource_names` in `scripts/macos_license_notices.sh`). Each
binary zip holds its executable plus `LICENSE`, `NOTICE` and
`LICENSE-THIRD-PARTY.html` at its root. Homebrew installs those root files into
the formula prefix. The app's two font license files stay with the fonts.

## The Rust notices

`LICENSE-THIRD-PARTY.html` is generated by cargo-about 0.9.2 from `Cargo.lock`,
with `licenses/about.toml` and `licenses/about.hbs`, for `aarch64-apple-darwin`.
It covers both binaries in one file: runtime dependencies plus build scripts and
procedural macros, since those can put third-party code or data into the
binaries. Dev-only dependencies and the workspace's own crates are left out.

The file is committed so license changes show up in review, and packaging needs
no network or extra tool. CI (`Public surface checks`) regenerates it and fails
when the committed file differs.

Regenerate it after any `Cargo.lock` change:

```bash
cargo install --locked --version 0.9.2 --features cli cargo-about   # once
bash scripts/generate_license_notices.sh
```

`--check` compares without writing. The generator also checks the special
license texts below, because cargo-about only warns, and falls back to a
generic text, when a clarification's file hash no longer matches.

### Dependabot and other lockfile updates

The weekly grouped Cargo update always changes the notices, so its first CI run
fails at `Third-party license notices`. To fix it, check out the Dependabot
branch, run the regenerate command above, review the HTML diff, and push a
commit made with a permitted public identity (the commit identity check in
`Public surface checks` rejects others).

If generation stops with a message naming `ring` or `webpki-roots`, that crate
changed version. Download the new crate, compute the SHA-256 of each file named
in its `licenses/about.toml` entry, read the text changes, then update the
hashes there and the pinned version in `scripts/generate_license_notices.sh`
(and in that script's text checks) in the same change. A new license
identifier fails generation until it is reviewed and added to `accepted`.

### Special cases

- `ring` 0.17.14: its `LICENSE` only points at other files. The clarification
  reproduces all five: `LICENSE-BoringSSL` (Apache-2.0), `LICENSE-other-bits`
  (ISC), the fiat-crypto notice `third_party/fiat/LICENSE` (Apache-2.0) and the
  bundled `once_cell` Apache-2.0 and MIT files.
- `webpki-roots` 1.0.12: the root certificate data is under
  CDLA-Permissive-2.0, whose full text must accompany the data.
- `objc2-core-foundation` and `objc2-core-services` 0.3.2 ship no license file
  and are offered under `Zlib OR Apache-2.0 OR MIT`. Ottto uses them under
  Apache-2.0, so they are listed with the full Apache-2.0 text.

## Sparkle

`Sparkle-2.9.2-LICENSE` is the `LICENSE` file of Sparkle 2.9.2, byte for byte
(6,154 bytes, 134 lines), from commit
`6276ba2b404829d139c45ff98427cf90e2efc59b`:
<https://github.com/sparkle-project/Sparkle/blob/6276ba2b404829d139c45ff98427cf90e2efc59b/LICENSE>.
Its SHA-256 is
`389a4e4e9a32f059775b13a06e25a591445ba229d2838d26dd3e7c0c45127cfe`. It covers
Sparkle and the code it bundles, under MIT, BSD and Zlib terms.

Packaging refuses an app whose Sparkle pin (from the app's committed
`Package.resolved`) or embedded framework version is not this release. To move
to a new Sparkle version, update this file, its name, and the version,
commit and SHA-256 in `scripts/macos_license_notices.sh` in one reviewed
change before the app's pin moves. Never fetch the license at release time.
